# 折扣变更的计算口径提醒

折扣仍以新增日期版本保存。弹窗同时展示现有版本、拟新增版本实际生效范围、当前 Dashboard 日期区间保存前后的分段口径。旧版本继续按消费日生效，新插入的早期版本只生效到下一个已有版本之前，不覆盖更晚版本。

缺历史版本的日期，在待核实试算中使用当前已生效折扣回推。预览明确区分历史版本、当前折扣回推和缺少折扣；因此新增当前版本即使起始日晚于所查看区间，也可能改变缺历史版本部分的试算。未来尚未生效的版本不改变当前回推。

预览只推演日期规则，不声称各日期均有费用；实际金额仍取决于已采集费用、FX 和成本核验状态。保存成功提示系数、UTC 生效日期和历史保留规则。选择已存在日期时直接提示冲突并禁用提交，服务端也返回 `DISCOUNT_DATE_EXISTS`，不会默默覆盖。

本轮不修改任何生产折扣或成本口径。纯函数 5 个用例覆盖实际 0.85→1 情形、未来版本、回溯插入、重复日期、0 系数及无效区间；后端集成验证生效范围元数据、重复日期错误码和旧版本保留。生产计算、试算和缓存函数 AST 未改变，沿用已记录的 R7 API 压测结果，后端测试与浏览器流程重新验证。

开发验证：策略纯函数 5/5；SQLite、PostgreSQL 各 43 passed / 1 skipped；TypeScript/Vite、Docker 构建通过。Chromium 已验证实时分段、旧 0.85 保留、当前折扣回推提示、同日冲突禁用、保存后提示与手机布局。测试仅在独立开发实例创建定价版本。

生产已上线并完成 HTTPS 登录、源文件校验及前端构建核对。既有 2026-11-09 / 0.85、2026-11-10 / 1 两个生产版本均保留，验收没有向生产新增折扣。VM PostgreSQL 回归通过后才激活；保留 R7 回滚镜像及升级前后备份。
