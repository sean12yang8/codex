# 首轮交付与架构决策

## 开发选择

独立 React/Vite 前端 + FastAPI 后端，以同源静态服务交付一个可运行镜像。SQLAlchemy 可连接 SQLite（本地）和 PostgreSQL（Compose）。本轮导入为有上限的同步请求，成功响应代表整批事务已提交；不伪造异步 Job 或进度。后续接入大文件与 Azure 后再拆分 Worker/优先队列。

数据库以首版建表建立，暂未引入版本迁移框架；后续表结构变更前需引入 Alembic，不能依赖 create_all 更新已有表。PostgreSQL 导入锁定订阅行；SQLite 单机串行事务，仅适用于开发。生产并发与吞吐需专项测试。

## 与 PRD 的本轮差异

- 客户先保存，租户/订阅随后添加；尚未实现新建客户 1–3 组 SP 一次提交及四阶段异步发现。
- SP 仅加密保存和轮换，AUTH/DISCOVER/COST/SYNC 未接入，不显示成功状态。
- CSV 仅平台标准模板；未声称兼容 Azure 原版格式。人工声明价格与完整度需要证据，不能代替真实 PoC。
- 客户/租户/订阅当前归属不可编辑，避免误改历史。后续通过显式生效日期的 Ownership History 实现转移。
- 折扣/汇率仅追加日期版本，不覆盖同日旧记录，按消费日查询；本轮按需计算，无异步物化汇总。
- Dashboard 有日趋势，暂无月粒度和环比；未知/缺失不填零。CSV 导出是有效成本服务日明细，不是 PRD 全量 Excel/日月维度汇总报表。
- 数据导入历史保留最近 100 条可见记录，底层保留全部批次。尚无服务端分页。
- 用户创建通过管理员终端命令；没有自注册、SSO、用户设置界面或账号禁用/密码重置界面。
- 不提供硬删除，避免未验证删除恢复链路前开放不可逆动作。

## 后续批次

1. 提供脱敏标准/原版 CSV、实际 CSP Scope、测试 SP、两个同月 Blob Export Run 与 Manifest 后，完成价格/权限/完整度 PoC，固定官方格式映射。凭据通过安全环境配置提供。
2. 接入 Azure API/Blob、后台 Worker、调度、优先队列、退避重试、取消、覆盖证据与历史回填。
3. 实现波动/零消费/失败告警、站内通知、邮件和 Teams；基线为零规则单独冻结。
4. Entra SSO、平台用户管理、凭据轮换、归属历史、分页/月度聚合/Excel、压测优化。
5. 备份保留/审计期限经业务和运维确认后，实现删除墓碑、恢复演练、生产安全及性能验收。

## 已采用的暂定规则

UTC 完成日统计；未验证费用不进入 ACR；USD 固定 1；折扣与汇率按消费日；凭据仅管理员配置；人工修正需原因，CSV 同一天全服务快照替换，部分范围不清空范围外记录。真实 Azure 全量自动采集和正式 ACR 结论均待验证。
