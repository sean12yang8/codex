# Azure GPT-Realtime 1.5 与 Azure GPT-Audio 1.5 网页端 MVP 场景规划

## 目标
在最小可运行（MVP）阶段，先验证两类核心能力：
1. **实时双向语音/文本交互（GPT-Realtime 1.5）**：低延迟、多轮会话、可中断。
2. **高质量音频理解与生成（GPT-Audio 1.5）**：稳定的语音输入输出、可控音色与内容结构。

---

## 产品 A：RealtimeTalk（基于 Azure GPT-Realtime 1.5）

### 1) 适用场景（优先）

#### 场景 A1：实时英语口语陪练（教育）
- **用户痛点**：传统口语练习反馈慢、互动感弱。
- **Realtime 优势**：
  - 用户说话过程中可被实时理解；
  - 模型可自然打断与追问，接近真人对话；
  - 低延迟提升“沉浸式”训练体验。
- **MVP 验证指标**：
  - 首字响应时延（TTFB）< 800ms；
  - 单次会话平均轮次 > 12；
  - 用户主观评分（流畅度）≥ 4/5。

#### 场景 A2：电商/官网实时语音导购
- **用户痛点**：移动端打字输入成本高，咨询转化低。
- **Realtime 优势**：
  - 用户“边看边问”，模型即时推荐；
  - 可根据用户语气和追问动态调整推荐策略；
  - 适合高频问答（价格、规格、库存、活动）。
- **MVP 验证指标**：
  - 平均咨询时长下降；
  - 有效咨询转化率提升；
  - 重复问题自动解决率。

#### 场景 A3：线上活动/展会实时问答助手
- **用户痛点**：活动现场问题集中，人工客服压力大。
- **Realtime 优势**：
  - 实时接听语音问题并即时回复；
  - 支持主持人模式（快速切换话题）；
  - 可做“最后 30 秒摘要”。
- **MVP 验证指标**：
  - 峰值并发下响应稳定性；
  - 人工客服转接率下降；
  - 用户留存时长提升。

### 2) MVP 页面功能建议（美观 + 最小可用）
- **单页应用布局**：
  - 左侧：对话历史（气泡 + 时间轴）；
  - 中间：动态波形与实时字幕；
  - 右侧：场景模板（口语陪练/导购/问答）。
- **关键交互**：
  - 一键开始/停止实时会话；
  - 支持“打断模型”；
  - 支持语音 + 文本混合输入。
- **视觉风格建议**：
  - 深色玻璃拟态背景 + 高对比强调色；
  - 波形动画与状态点（Listening / Thinking / Speaking）；
  - 卡片圆角、轻阴影、留白充足。

### 3) 为什么放在 Realtime 而非 Audio
- 该类场景核心是“低延迟互动与会话节奏”，而非离线或半实时内容处理。

## 产品 B：AudioStudio（基于 Azure GPT-Audio 1.5）

### 1) 适用场景（优先）

#### 场景 B1：内容创作者“一键口播稿 + 配音”
- **用户痛点**：写稿与配音工具分散，制作链路长。
- **Audio 优势**：
  - 文本生成可直接转语音；
  - 语速、语气、风格可控；
  - 可快速产出短视频口播版本。
- **MVP 验证指标**：
  - 从输入主题到导出音频 < 2 分钟；
  - 首次可用成片率；
  - 复用率（同模板再次生成）。

#### 场景 B2：客服质检与通话摘要（语音理解）
- **用户痛点**：客服录音分析依赖人工抽检，效率低。
- **Audio 优势**：
  - 音频转文本 + 结构化摘要；
  - 自动提取风险话术、情绪变化、关键承诺；
  - 可生成“改进建议”。
- **MVP 验证指标**：
  - 摘要准确率（人工评估）；
  - 风险点召回率；
  - 单条录音处理耗时。

#### 场景 B3：无障碍信息服务（文本↔语音）
- **用户痛点**：视障/阅读障碍用户获取信息成本高。
- **Audio 优势**：
  - 文本高质量朗读；
  - 语音输入后生成清晰结构化文本；
  - 支持多语言播报。
- **MVP 验证指标**：
  - 可理解度评分；
  - 完成任务时长；
  - 用户复访率。

### 2) MVP 页面功能建议（美观 + 最小可用）
- **双栏工作台**：
  - 左栏：输入区（上传音频/输入文本/模板选择）；
  - 右栏：输出区（转写文本、摘要卡片、音频播放器）。
- **关键交互**：
  - 一键“转写 + 摘要”；
  - 一键“文本转语音”；
  - 导出 txt / srt / wav。
- **视觉风格建议**：
  - 浅色专业工作台风格；
  - 语义标签色（摘要、风险、行动项）；
  - 输出卡片可折叠，信息层级清晰。

### 3) 为什么放在 Audio 而非 Realtime
- 该类场景核心是“音频内容处理质量与产出效率”，可容忍秒级到分钟级处理时延。

---

## 两个接口的场景划分原则（决策速查）
- **优先选 Realtime 1.5**：
  - 强依赖“对话实时性”；
  - 需要可打断、可插话、连续多轮；
  - 用户体验关注“像真人通话”。
- **优先选 Audio 1.5**：
  - 强依赖“音频理解/生成质量”；
  - 有文件上传、批量处理、结构化输出；
  - 用户体验关注“结果质量与可导出”。

---

## 建议的 MVP 实施顺序
1. 先上线 **RealtimeTalk（A1 口语陪练）**，最容易验证实时交互价值。
2. 再上线 **AudioStudio（B1 口播生成）**，最容易形成可展示成果。
3. 两个 MVP 共用统一账号体系与日志分析面板，降低研发成本。
