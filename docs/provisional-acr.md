# 待核实 ACR 试算

用户确认先按明确标注的假设预览内部 ACR，尚未确认 ActualCost 是否已经包含客户折扣。试算假设来源为折扣前基数，按“原币成本 × 客户折扣 × USD 汇率”计算；不能因此标记来源已核实。

已有历史折扣版本时仍按消费日查版本。用户另确认：没有历史版本的更早日期，可仅在试算中按该客户当前已配置折扣回推。本租户当前配置为 2026-11-09 生效、85%；回推不新增或修改历史折扣记录。各区间、历史累计均返回回推记录数。

缺少任何已生效折扣和当前可回推折扣、或缺少消费日适用 FX 的费用保留为不可计算，不补零。USD 汇率固定 1。混合币种在各自行有效汇率换为 USD 后才可汇总。历史归属、删除范围、显式零与缺失日期逻辑沿用原有规则。

Dashboard 的 `estimate` 是独立的只读试算字段，包含金额、趋势、客户排行、待核实条数、缺失原因及回推元数据。`total`、`lifetime` 等已核验字段保持原有条件；试算不修改 Batch.verified，不触发可信 ACR 告警，不自动写入标准报表的已核验金额。界面提供“含待核实试算 / 仅已核验”切换，并显示假设说明；标准导出标注为已核验报表。

SQLite/PostgreSQL 集成回归覆盖：未核实试算 255 USD 与可信 ACR 空值并存、未修改 Batch 标志、标准 CSV 仍不填可信金额、混合币种换算、历史版本优先、缺历史版本当前折扣回推、补历史版本后撤销回推、已核验来源缺历史折扣只能出现在试算、未核实零试算不触发可信零消费告警。

当前完整后端回归：SQLite / PostgreSQL 各 42 passed / 1 skipped；TypeScript/Vite 和 Docker 构建通过。浏览器验收与真实生产恢复记录在验证文档中补充。

生产 HTTPS 验收：本月 56 条费用可试算，56 条采用待确认假设，其中 49 条使用当前折扣回推；历史累计 2,365 条可试算，2,358 条回推。试算金额及历史累计均精确等于对应 USD 原始成本乘 0.85，9 个日趋势点和客户排名均可返回。来源批次仍未核实，已核验区间金额仍为空；历史折扣未修改。检查发现接入口径设置与历史批次不一致，依据用户本次明确“尚未核实”的确认，将接入标记恢复待核实，保留原说明并经管理 API 留存审计，防止后续误标新批次。前端构建哈希核验通过。
