# Cost 同步内部异常（2026-11-10）

## 定位

用户截图任务 `80dd17e2`，消费范围 2026-11-03 至 2026-11-09，0/1 分区。生产中身份认证与订阅发现已成功（3 个订阅），尚无有效费用。一次只读诊断得到 Azure 200，但在 `query_cost → dec` 抛出 HTTPException，被 Worker 通用分支映射为 INTERNAL_WORKER_ERROR。

根因是原始成本复用了手工折扣/汇率的 12 位小数限制，Azure Cost 数值超过该限制时被拒绝。原测试直接模拟归一化费用，未经过真实形状的 Azure JSON 数字解析，因此漏掉此问题。

同时观察到 429：原逻辑未发送固定 ClientType，并只读标准 Retry-After，未读取 Cost Management 专用的限流等待头。

## 修复

- 原始 Cost（API、Azure/标准 CSV、有效分区发布）允许最多 60 位小数，在 Decimal 上下文内保留原值，不转换浮点或先舍入至分；折扣/汇率等配置仍保持 12 位限制。
- 不合法的上游金额/行返回 COST_INVALID_AMOUNT / COST_INVALID_ROW，而非笼统内部异常。
- Cost 请求携带固定 ClientType=AzureLens，遵守配额，不使用随机标识规避限流。读取标准秒数/HTTP-date 和专用 entity/tenant/clienttype/qpu 等 retry-after，取最大等待提示；429 无有效提示时至少默认 60 秒。
- 未预期异常仅记录异常类和源码位置，禁止记录异常正文、SQL 参数、局部变量、令牌和凭据。
- 同步中心展示 Azure 限流说明与下次尝试时间。

## 回归

新增 Azure 形状 JSON → 数字解析 → Worker → 原始批次/有效费用 → Dashboard 的完整回归，覆盖 29 位小数及负数修正；同样验证 CSV 入账、折扣配置精度限制、非法金额、专用限流头、HTTP-date、重试截止时间与日志不含异常秘密。

SQLite 和 PostgreSQL 各 35 passed / 1 skipped；TypeScript/Vite 构建通过。真实生产恢复结果另记录在部署验收中，未以测试夹具替代真实数据。
